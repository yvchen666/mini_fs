# minifs 设计说明

## 目标

用尽量少的部件把“存储”和“文件”分开，并且每一层都能单独看懂。

存储层回答：这块盘有多少个 4KB 块，哪一块是空的，怎样把一块读出来、写回去。

文件层回答：`/docs/hello.txt` 这个名字对应哪个对象，对象的字节存在哪些块里。

demo 保证的是：一次 API 调用返回成功，并且进程正常 `unmount` / 退出之后，再次 `mount`，目录和文件内容一致。它不保证进程在一次调用的中途被杀掉后仍然完全没有泄漏。

## 模块

| 模块 | 文件 | 做什么 |
| --- | --- | --- |
| 类型和布局 | `include/minifs/types.hpp` | 超级块、inode、目录项、错误码 |
| 位图 | `include/minifs/bitmap.hpp` | 置位、清位、找第一个空位 |
| 块设备 | `src/block_device.cpp` | 把镜像文件按块号读写 |
| 镜像 | `src/fs_image.cpp` | 格式化、挂载、分配 inode 和数据块 |
| 路径和目录 | `src/fs_path.cpp` | 解析路径，增删目录项 |
| 文件字节 | `src/fs_file.cpp` | 偏移换块号，读写，截断，文件描述符 |
| 交互 | `src/shell.cpp` | 上面这套 API 的命令行 |
| 自检 | `src/self_test.cpp` | 格式化、跨块、重挂载、删光后空间回收 |

`FileSystem` 的公开接口在 `include/minifs/filesystem.hpp`。磁盘细节放在 `src/fs_impl.hpp`，shell 碰不到块号。

## 磁盘布局

默认镜像是 256 个块，每块 4096 字节，一共 1 MiB。inode 固定 64 个。

```text
块 0        超级块（魔数 MFS1、块数、inode 数、空闲计数、根 inode）
块 1        块位图。1 表示占用
块 2        inode 位图
块 3        inode 表。64 个 inode × 64 字节 = 正好 1 块
块 4 ..     数据区。文件内容和目录项都在这里
```

格式化时块 0 到块 3 标成已占用，再给根目录分配 1 个数据块。所以格式化结束后空闲数据块是 `总块数 - 4 - 1`，空闲 inode 是 63。

inode 是 64 字节：类型、大小、链接数、12 个直接块指针，以及 4 字节补齐。链接数第一版恒为 1，没有硬链接。直接块指针为 0 表示这个逻辑块还没分配。块 0 永远是超级块，不会被当成数据块，所以 0 可以当空指针。

目录项是 32 字节：inode 号加 28 字节名字（最长 27 个字符，末尾留 0）。inode 号 0 是根目录，因此目录里的空槽用 `0xFFFFFFFF`，不能用 0。

一个目录就是普通的字节流，内容是连续的目录项。`.` 指向自己，`..` 指向父目录，根目录的 `..` 指向根自己。删除名字时把这一项标成空槽，目录大小不缩小；下次创建优先把空槽填上。

文件和目录都只用 12 个直接块，所以最大 48KB。超过这个长度直接返回错误，不去实现间接块。

## 路径

只接受绝对路径，例如 `/docs/a.txt`。`/` 是根。中间的 `.` 和 `..` 靠目录里的那两项解析，不在字符串上特殊折叠。最后一级如果是 `.` 或 `..`，不能作为 `mkdir` / `touch` 的新名字。

`lookup` 从根 inode 开始，每一级都必须是目录，然后线性扫描目录项。demo 的目录很小，线性扫描足够，也最好读。

## 一次写入发生了什么

以 `write /docs/a.txt hello` 为例：

1. 找到父目录 `/docs` 和名字 `a.txt`。没有这个文件就分配一个 inode，类型写成普通文件，再往父目录追加一项。
2. 打开时用截断模式，先把旧数据块还回位图，大小改为 0。
3. 按偏移算出“第几个逻辑块”和块内偏移。逻辑块还没有物理块时，分配一块。
4. 分配的顺序是：内存里把位图置位，先把位图和超级块写回镜像，再把这块清零，最后才让 inode 的直接指针指向它。
5. 读出这一整块，改掉要写的那一段，写回数据块，更新 inode 的大小和指针，再 `sync`。

跨过 4096 字节时，第 5 步会碰到第二个逻辑块，于是再分配一块。自检用 5000 字节覆盖这条路径。

删除文件时顺序相反：先从目录拿掉名字，再把 inode 里的指针清掉并同步，最后才把块和 inode 号还回位图。这样位图里重新变成空闲的块，已经不会被任何 inode 指着。

## 崩溃时的取舍

没有日志，不能承诺“任意时刻断电都完全不丢、也不泄漏”。

当前顺序故意选泄漏，不选把还在使用的块再分出去：

- 新块先在位图里标成占用并落盘，然后才写 inode 指针。中途退出时，这块可能谁也不指向它，但下一次分配不会把它交给别的文件。
- 释放时先把 inode 指针清掉并落盘，再清位图。中途退出时，块可能暂时还不回来，但不会被第二个文件同时使用。

如果超级块里的空闲计数和位图对不上，`mount` 会拒绝这个镜像并返回“损坏”。修复手段就是重新 `format`。这是 demo，不是一个掉电安全的文件系统。

## 第一版不做的事

- 用户、权限、时间戳
- 日志或写时复制
- 缓冲缓存。每次都直接读写镜像文件
- 间接块、硬链接、`rename`、`seek`
- 多进程和锁
- 目录缩容。空槽只复用，不把目录文件截短

接下来如果要加一件事，最值当的是块缓存：现在每读一个 inode 都要读一整块 inode 表。缓存不改变磁盘格式，适合作为第二层练习。
